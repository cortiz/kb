# Contract: what a release is

## Tag

`v<major>.<minor>.<patch>` with an optional `-<identifier>[.<identifier>…]` suffix, where the part
after `v` equals the workspace version in `Cargo.toml`, on a commit reachable from `main`.
Pre-release = has a suffix. Examples: `v0.2.0` (stable), `v0.2.0-rc.1` (pre-release).
Anything else (`latest`, `v1`, `release-3`, `v1.2.3abc`) does nothing or fails fast with a message.

## Assets (five files)

```text
kb-0.2.0-aarch64-apple-darwin.tar.gz
kb-0.2.0-x86_64-apple-darwin.tar.gz
kb-0.2.0-aarch64-unknown-linux-musl.tar.gz
kb-0.2.0-x86_64-unknown-linux-musl.tar.gz
SHA256SUMS
```

Archive layout (each):

```text
kb-0.2.0-<target>/
├── kb              (0755)
├── README.md
├── LICENSE-MIT
└── LICENSE-APACHE
```

`SHA256SUMS` has one line per archive, `<64 hex>  <file name>`, sorted by file name.

Archives are reproducible: fixed file order, zero owner, modification time = the tagged commit's
time, gzip without name or timestamp.

## Notes

Generated by git-cliff from Conventional Commits since the previous release tag, sections in this
order: Breaking changes, Features, Fixes, Performance, Documentation, Other. With nothing
user-facing: "No user-facing changes." Every platform is smoke-tested on a machine or emulator of its
own kind (the Intel Mac binary on an Intel runner); if one cannot be, the release stops rather than
publishing an untested binary.

## Provenance

When the repository is public: a build provenance attestation per archive, verifiable with
`gh attestation verify <archive> --repo cortiz/kb`. While private: skipped, and the run summary says
so.

## How a user verifies and installs

```sh
# download the archive for your machine and SHA256SUMS from the release page, then:
shasum -a 256 -c --ignore-missing SHA256SUMS          # macOS;  sha256sum -c --ignore-missing on Linux
tar -xzf kb-0.2.0-aarch64-apple-darwin.tar.gz
./kb-0.2.0-aarch64-apple-darwin/kb --version
gh attestation verify kb-0.2.0-aarch64-apple-darwin.tar.gz --repo cortiz/kb     # public repo only
```

Homebrew (after the repository is public, stable releases only):

```sh
brew tap cortiz/kb https://github.com/cortiz/kb
brew install kb
```

macOS shows a Gatekeeper warning for a downloaded binary because it is not notarized (out of
scope); `xattr -d com.apple.quarantine kb` or installing with Homebrew avoids it.

## Smoke test (per built binary, before packaging)

In a fresh temporary directory with `KB_ROOT` pointing into it and an empty `HOME`:

1. `kb --version` prints `kb <version>` (the tag's version).
2. `kb init` exits 0 and creates the examples.
3. `kb lint --strict --quiet` exits 0.
4. `kb search lambda --ids` exits 0 and prints at least one ID.
5. `kb doctor --json` exits 0 and its output parses as JSON with `"ok": true`.
